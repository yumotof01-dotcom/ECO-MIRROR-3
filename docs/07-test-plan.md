# 07｜品質保証・検証計画 v0.1

## 品質のゲートを分離する

| ゲート | 検証 | 必須結果 |
|---|---|---|
| G0 設計整合 | 画面/用語/来歴/schema/READMEの矛盾 | 重大な矛盾0、設計テストPASS |
| G1 移植一致 | 旧版固定データで440条件と橋の全件数値を比較 | 未説明差分0 |
| G2 データ品質 | 地図元クラス、座標系、欠損、派生SHA、ライセンス | 許可されたすべての入力は検証成功、破損は拒否 |
| G3 研究性能 | 実在する6地域と4km大型窓 | 全条件終了、メモリ/時間を計測、上限の失敗表示 |
| G4 UI操作 | Desktop/Tablet/Mobile、キーボード/読み上げ | 指定ユーザー操作を完了し、誤認・誤表示なし |
| G5 セキュリティ/公開 | CSP・静的アセット・依存ライセンス/脆弱性 | 意図しないデータ送信なし、秘密鍵なし |
| G6 科学的説明 | 事例の解釈と外部監査 | 観測・モデル・仮説・未実証が区別される |

## 旧版から引き継ぐ数値回帰基準

- 実際の6地域の土地被覆セル合計 **240,000**、新宿4km追加 **160,000**（重複あり）。
- ベースライン **3,080**件、選択した16地点×6地域の仮想改善 **42,240**件。
- 5,000の合成小格子・25,001の数理条件、268種類の実地データ改変ケース。
- パッチ3,541個の現実実行、4,001個以上の明示的な安全停止。
- 旧版既存テスト **328件**の合格は「旧版」の検証値。**新アプリ移植済みを意味しない**。
- 旧版の大型実地例は Linux ランナーで440条件約10.57秒、最大RSS約269MiB。新アプリでの速度は測定し直す。

## 新アプリ側で追加する必要があるテスト

1. 誤った地域の結果が混入する事故：取得要求が古くなった場合は表示拒否。
2. 出典が欠落した結果の描画：本番結果として採用拒否。
3. データ未接続でPCを0として表示する事故：プレースホルダーだけ。
4. UIが `440/440` の完了を示すとき、実データの全440条件の実行・検証状態が一致。
5. スマホ回線で段階的読み込み、低メモリ時の中断/回復。
6. Safari/iPad、Chrome、Firefoxでの描画・ダウンロード、キーボード・読み上げ。
7. OSのreduced-motion、文字拡大200%、高コントラスト。
8. エクスポートJSONにデータ年、モデル、SHA、全警告、出典がそろう。
9. 構造PCが上がってもパッチが結合していない場合、画面が「橋が完成」と表示しない。
10. 統計や順位の計算に与えた440条件を、将来の発生確率として誤って説明しない。

## 暫定性能目標（まだ達成していない）

- 端末条件を明記した上での初回主要UI表示・応答時間を計測する。
- 地図のパン/ズームがメインスレッドを長時間塞がないこと。
- モバイルでの初期通信容量、メモリ、ダウンロード中断/復帰を測定。
- 画面用パッケージは圧縮・分割し、全シナリオの大量JSONを起動直後に読み込まない。
- 重い計算はWorkerに隔離し、操作時の取消が有効に機能すること。

**数値性能の固定しきい値は、最初の実機測定結果で合理的に設定する**。未測定のまま「3秒以内」「全スマホ対応」と宣言しない。

## 結果の保存

テストにはコミットSHA、ブラウザ、OS、ハードウェア・地図版、入力ハッシュ、結果ハッシュ、成功/失敗、失敗理由を残す。結果の警告と未実証を利用者向け画面の文言にも反映する。
