# 08｜開発ロードマップと各段階の合格条件

## 進め方

**設計 → 新リポジトリ → 計算の安全な移植 → 事前計算パッケージ → 地図UI → 条件UI → 実地検証 → 公開**の順で実施。ユーザーの目標は科学的に根拠あるアプリなので、データを接続する前に華やかな擬似シミュレーションを正式な機能として表示しない。

| 工程 | 作るもの | 合格基準 | 状態 |
|---|---|---|---|
| 0 | 独立新Repo・初期設計 | 旧Repoを変更せず仕様が揃い、GitHubに新Repoが存在する | **完了：別Repoを作成して初期設計を配置（Public）** |
| 1 | React/TypeScript/Vite 新アプリの基本骨格 | 起動・ビルド・キーボードで全ナビ可・空状態明示 | **実装済み：CIと実機ブラウザの検証を別途記録** |
| 2 | 旧研究エンジンの選択的移植 | 固定版6地域の440条件・橋の数値を再計算し一致 | **完了：16ファイルの原本照合、3,080条件と42,240比較の新旧全バイト一致（研究CLIのみ）** |
| 3 | データセットの静的配布/来歴検証 | 版・SHA・出典・年の検証を通過、破損は失敗表示 | 未着手 |
| 4 | 地図ワークスペース | 2Dデータ表示、分類凡例、表形式代替、縮小画面確認 | 未着手 |
| 5 | 440条件比較 | 完全な条件選択、PCと仮説の区別、処理中断 | 未着手 |
| 6 | 限界点・自然の橋 | モデル急変/トポロジー/PC増分を独立表示 | 未着手 |
| 7 | エクスポート・研究根拠 | 保存後に第三者が元データと条件を特定可能 | 未着手 |
| 8 | 総合テスト・公開前審査 | WCAG、実機、異常入力、性能、ライセンス、脆弱性確認 | 未着手 |

旧リポジトリで第1〜4工程に相当する**研究計算基盤は別途実装・検証済み**。ここでいう新しい工程は**新アプリ側**の作業であり、研究コードの存在を新アプリ実装済みと誤認しない。

## 初期リリース判定

- 地域固定のMVP：6地域の事前計算済み研究パッケージを対象。任意地域の再計算は要望があっても別途設計と検証が必要。
- 法的・科学的な宣言が必要な「生物の実際の移動」や「保全候補地の推薦」はMVPの公開説明に含めない。
- 旧ECO MIRRORの公開がまだなら、旧版リンクの到達可否を公開前に確認する。
- 永続データを使わない無料の静的配信が成り立つ場合のみ公開を検討する。

## 利用者の意思決定が必要になるタイミング

- 新リポジトリのPublic化：コンテスト提出のため利用者が承認済み。GitHub上の表示を確認して完了判定する。
- 新アプリの名称・ロゴ・ライセンス・ドメインを正式に決める時。
- UIのデザイン方向性を確定して、開発を進める時。
- 本番公開/ドメイン/個人データの取得が必要になった時。

## 費用の考え方

- **追加必須月額0円**を目標にする。計算はローカル/CI、公開配信は無償の静的ホスティング枠を想定。
- GitHub/ホスティング/自動化の無料範囲や制限は公開時点で再確認し、勝手に有料化・課金しない。
- 研究元データの権利と、アプリのコードライセンスは別に決める。
