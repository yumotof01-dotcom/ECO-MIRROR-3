# 12｜実装開始前の受入基準

## フェーズをまたぐDoneの意味

- **設計Ready**：再現可能な仕様書・データ契約・UI情報設計・テスト方針・リスクと未検証事項が文書化され、設計プロトタイプを表示できる。
- **コードReady**：新RepoでReactアプリが実在し起動し、旧版から移植した数理計算に旧結果との差分がない。
- **研究データReady**：出典・ライセンス・元分類・SHA・条件IDを接続し、検証済み結果を画面で表示できる。
- **製品Ready**：モバイル・デスクトップ・キーボード・読み上げ・停止/再試行・データエクスポートの実機検査に合格。
- **科学的実地効果Ready**：別途定義した生物学的な野外調査で評価できたときにのみ判断。製品Readyの前提条件ではないが、未実証表示は必須。

## 主要な受け入れシナリオ

| 場面 | 期待する挙動 |
|---|---|
| 新宿→大阪へ地域変更 | 旧新宿の440結果を大阪の結果として表示しない |
| 現地データ未接続 | 「データ未接続」で停止。PC=0のグラフを生成しない |
| ESAのSHA不一致 | 結果を出さず破損理由を表示 |
| PC改善・パッチ未結合 | 「構造的PCが増加、直接パッチ結合なし」と表示 |
| 仮想除去30→35% | 「モデル上の変化」であり、「生態系崩壊」と表示しない |
| 低性能端末 | 事前計算結果を先に表示し、重い計算は中止可能 |
| 不完全なシナリオ | `440/440完了` と宣言しない |
| 結果保存 | 同じデータ版、モデル版、条件、出典、警告を保存 |
| キーボードのみの操作 | 地図の主要情報を表/ボタンで取得できる |

設計上の仕様は初版。ユーザー体験の検証やアクセシビリティ監査を行うまで「合格済み」とは言わない。
