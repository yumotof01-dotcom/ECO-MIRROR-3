# 23｜準備⑧：UI・UX設計への引き渡し仕様 v1

更新：2026-11-06。実装上の正本：`src/research/uiContract.ts`。
この仕様は情報・操作・状態・科学的な説明の要件を固定する。正式なレイアウト、色、書体、アニメーションは次のUI・UX設計で扱う。

## 利用者ができること

1. 6地域から研究範囲を選び、データ年と出典を確認する。
2. 土地被覆と植生候補のパッチを4/8近傍で調べる。
3. 440条件内の仮定を変え、PCと面積の違いを比較する。
4. 11段階の曲線と最大低下区間を読み、非単調性などの警告を見る。
5. 400㎡の仮想追加候補を同条件で比較し、PC増加と直接結合の違いを確かめる。
6. 出典・条件・結果を保存し、再読込時に検証して確認する。

任意住所検索、現在の生物分布の断定、将来確率、現実の施工推薦は機能として約束しない。

## 四つの研究モード

| モード | データの入口 | 必須表示 | 操作と注意 |
|---|---|---|---|
| connectivity | prepareResearchMap / candidateFootprint | 元分類の年、凡例、範囲、植生面積、4/8近傍 | 地図は構造モデルの入力。生物の移動線を描かない |
| scenario | condition / compare | 基準と比較条件、変更軸、PC、面積、実除去率、差 | lambdaは仮説。複数軸変更を隠さない |
| threshold | curve | 11点、最大低下区間、診断状態、非単調性と警告 | 「絶滅・崩壊の閾値」と表示しない |
| bridge | rankedCandidates / intervention / compareCandidates | 400㎡、元分類、候補集合、PC効果、パッチ結合、新島化 | 12候補内の順位。参照4地点と区別。実施可能性未評価 |

## 条件と地域

- 地域：shinjuku / osaka / nagoya / fukuoka / sapporo / odaiba。
- lambda：40 / 60 / 90 / 135 / 200 / 300 / 450 / 675 / 1000 / 1500m（仮説）。
- 仮想除去：0〜50%、5%刻み。元の植生候補から除く割合。
- 近傍：4 / 8。規則：distributed / edge_first。
- 計440条件。補間・丸め・440通りの確率表示を行わない。
- 比較は同地域・同データ版に限定。別地域比較を追加する場合は別仕様にする。
- 地図のパッチIDは条件ごとに再採番される。個体や年をまたぐ追跡IDではない。

## 指標の表示規則

| 項目 | 表示の意味 | 0・nullの扱い |
|---|---|---|
| PC | 重心距離と植生候補面積による構造的接続性 | 計算済み0は0。欠測を0に変換しない |
| deltaPc | 比較後−比較前 | 正・負・許容差内を文字でも区別 |
| relativeChange | 差÷比較前PC（比率） | 基準0ならnullと理由。画面で%化するなら100倍し単位を明示 |
| vegetationAreaM2 | 仮定下の植生候補面積 | m²。丸め表示しても保存値は丸めない |
| patchesJoined | 連結成分数の減少分 | 正値は成分数の減少。PC増加だけでは結合と呼ばない |
| actualLossPercent | セル数丸め後の実除去割合 | 指定割合との差がある場合は隠さない |

確定前の書体に依存する桁数やグラフ軸はここで固定しない。元値はAPIから保持し、ラベルとツールチップ・表で条件を確認可能にする。

## 状態と操作

| 状態 | 見せるもの | 有効な操作 |
|---|---|---|
| idle | 地域/結果の選択案内 | 地域選択、ファイル読込 |
| loading | 対象地域・条件・処理中 | 中止と地域変更。地域検証済みなら条件の再変更も可。古い数値/地図を新条件として表示しない |
| ready | 検証済み結果と根拠 | 条件選択、比較、保存、ファイル読込 |
| empty | 該当候補なし等の理由 | 選択変更、ファイル読込。0のグラフで代用しない |
| cancelled | 中止したことを文字で明示 | 再試行、選択変更 |
| error | 安定したエラー文と回復方法 | retryableの場合のみ再試行。データ不整合では結果を隠す |

`ResearchSession`は地域、`ResearchMapSession`は地域＋地図条件のlatest-request管理を行う。新要求時に前結果を消し、古い応答を無視する。
ファイルのparse成功はreadyではない。replay成功の`verified_replay`のみ結果表示へ進める。ファイルの変更中はAbortControllerと要求番号で旧読込を無効にする。
`researchActions`はready以外で比較/保存を許可しない。地域が検証済みで地図だけloadingの場合はregionVerifiedを渡し、次の条件へ切り替えられる。`researchCapabilities`でWeb Crypto/Worker/Blobの能力を確認し、非対応機能は理由を示す。代替同期計算でUIを停止させない。

## 根拠とエラー

結果にはrelease、地域、データセット、原分類/マスクSHA、CRS、出典URL、帰属、ライセンス、2021年、注意事項へ到達できる導線を必須とする。
`researchErrorMessage`の通信・欠損・版不一致・検証不可・非対応ファイル・取消の分類を使う。内部パス、スタック、インポートしたHTML文字列をそのまま表示しない。

## アクセシビリティの受入条件

- マウスなしで地域・条件・比較・取消・保存/読込に到達できる。
- タブは矢印/Home/End、操作状態はaria-selected。フォーカス位置を更新のたびに奪わない。
- loading/成功/失敗/取消をlive regionで通知。音声通知の重複を避ける。
- 色だけで分類・増減・結合を伝えない。数値・文字の凡例を付ける。
- Canvas/SVGだけで完結せず、同じ主要結果を表と説明で取得できる。
- 縮小幅、拡大、動作軽減に対応する。正式画面完成後に再検証する。

## 受入シナリオと設計着手の判定

| シナリオ | 必須結果 |
|---|---|
| 新宿の取得中に大阪を選ぶ | 最終結果は大阪。新宿が遅れて完了しても置換しない |
| 地図の0%処理中に50%を選ぶ | 前地図を新条件として残さず、50%だけready |
| 通信が切れる/ファイル欠損 | 明示的な失敗。0や前地域の値に代用しない |
| 保存JSONのPCを変更し再ハッシュ | 固定データとの再照合で拒否 |
| PCが上がりパッチ数は同じ | 「PC増加」と「直接結合なし」を両方表示 |
| 基準PCが0 | PC=0を保持。相対変化だけ未定義と説明 |
| 結果保存→別の人が再読込 | データ版・条件・出典・注意事項を確認し再照合できる |

準備①〜⑥の機能、自動化した⑦の証拠、この⑧の仕様がそろえば情報設計とワイヤーフレームへ進める。
物理端末・VoiceOver等の未検証項目は[文書24](24-physical-device-checklist.md)に残す。製品完成・一般公開の承認とは分ける。
次は情報設計→低忠実度ワイヤーフレーム→操作の評価→配色/形/動き。その時点で実験値やモデルの意味をデザイン都合で変更しない。
