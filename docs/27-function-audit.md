# 2026-11-08 機能監査

監査対象はPR #7の1453fb3と、その監査で見つけた候補選択リセットの修正。外観の改修より機能確認を先に行う。

## 確認済みの範囲

- `npm run check`で設計契約、Reactの操作、研究エンジン、1000ケースの境界条件、保存形式、型検査、ビルドを再実行。
- `npm run research:build`で独立研究APIのビルドを確認。
- `audit-static-packages.mjs`で6地域、115ファイル、2640基本条件、42240追加候補比較を元データと照合。
- 既存ブラウザ試験は375/820/1366pxで地図、条件変更、PC原値との照合、曲線、候補、JSONダウンロード、通信失敗と回復、地域切替、キーボード操作を確認する。
- 今回ブラウザ試験を6地域へ拡張。各地域のλ10種類、8近傍・縁から除去・50%条件を画面経由で選択し、PCを配信元の値と照合。候補を選択して条件を変えた場合の選択維持も確認する。
- 取消・タイムアウト・Worker異常・旧応答の無効化・保存ファイル改変は既存の基盤テストで検証する。これらすべてを画面経由で実行したという意味ではない。

## 発見して修正した不具合

自然の橋で2番目の候補を選び、λを200mから300mへ変更すると、選択が先頭候補へ戻った。React試験で期待値 `connector-x22-y16` に対し `connector-x140-y138` となることを再現。

地図更新中に候補コンポーネントが破棄され、再表示時に内部の選択状態が初期化されることが原因。候補IDを地域の研究画面側で保持し、条件変更後も同じ候補を読むよう修正した。地域変更時には画面ごと初期化する。変更対象は候補選択状態の保持場所と引き渡し。

## 任意地点対応の具体的な制約

`App.tsx`の選択肢、`verifiedStudyLoader.ts`のRegionId、6地域を要求するマニフェスト検証、`ingest_worldcover.py`の`--site`選択肢が固定されている。研究版のマニフェストSHAも固定される。石神井公園の名前だけを選択肢へ追加しても必要なデータは作られない。

2021年の土地被覆、10m解像度、2km四方という現行条件を引き継ぐか、指定可能な範囲を変えるかを設計する必要がある。画面で自由な場所を指定する利用を実現するには、現行の固定6地域の提供経路を拡張する必要がある。

既存機能の試験と不足機能の確認を分けて記録する。全予定機能が完成した状態とは判定しない。最終コードのCI結果はPR #7のActionsで確認する。
